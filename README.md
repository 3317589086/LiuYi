# 六一 · 桌面宠物 v2.1.1 — 优化说明 / 使用说明 / 评价

小猫叫**六一**，是一只海豹双色布偶。`desktop_pet_v2.1.py` 基于 v2.0 重写，**接口不变、老配置自动沿用**。1362 行，单文件，依赖仍只有 `PyQt5==5.15.11`。

## 使用说明

### 跑起来

```powershell
pip install PyQt5==5.15.11     # 只装一次
python "D:\Download\六一桌宠\desktop_pet_v2.1.py"   # 这是启动器, 代码在 ragdollpet\
```

- 双击 `desktop_pet_v2.1.py` 也行（关联了 .py 的话）。
- **自动单实例**：重复启动不会出现两只猫，第二次启动会把已经在跑的那只叫到前面然后自己退出。
- 关掉窗口（Alt+F4）＝退出程序并保存位置，不会留后台进程。

### 它什么时候会做什么

| 状态 | 触发条件 | 表现 |
|---|---|---|
| 待机 | 默认 | 呼吸起伏、随机眨眼、偶尔甩尾，18–35 秒说一句 |
| 散步 | 待机 60–120 秒后 | 两/三帧步态交替，水平移动 2px/帧，撞到屏幕边自动转身 |
| 浅睡 | **5 分钟**没碰它 | 换睡觉图 + 慢呼吸 + Zzz，鼠标悬停即醒 |
| 深睡 | **10 分钟**没有键盘鼠标（全系统） | 同上 + 整体半透明 0.55，动一下键鼠 1 秒内醒，35% 概率说"你回来啦" |
| 被摸 | 单击 | 眯眼蹭头 0.7 秒 |
| 炸毛 | 350ms 内连点第二次 | 跳一下 + 炸毛台词 |
| 跳跃 | 没有 `cat_pet.png` 时的单击 | 跳一下 + 台词 |

两个时间都能在设置里改，浅睡和深睡互不干扰（浅睡按"没摸猫"算，深睡按"人不在"算）。

### 鼠标 / 键盘

| 操作 | 效果 |
|---|---|
| 左键单击 | 摸它（眯眼） |
| 快速连点 | 炸毛跳 |
| 左键拖动 | 拖着换位置，**拖不出屏幕**（至少 80px 留在屏内） |
| 滚轮（指在猫身上） | 缩放 0.5×–2.5×，只吃猫身体那部分的滚轮，旁边滚是滚桌面 |
| 右键 | 打开菜单 |
| 悬停 | 浅睡时叫醒它 |

猫身上的"可点区域"是跟着图片轮廓走的（窗口 mask），点透明的地方是点桌面。

### 说话气泡

气泡现在是**贴着六一的头顶**（间隙 6px），不再按窗口顶边算——窗口顶部有 64px 透明留白，旧版气泡离猫头有 95px，看着像飘在半空。睡觉时六一压低，气泡也会跟着降到它实际的头顶；头顶放不下才翻到脚下。

启动时会说一句「我是六一，今天也陪着你～」，喝水提醒、设置窗口标题、右键菜单也都带上了名字。

### 右键菜单

| 菜单项 | 说明 |
|---|---|
| 始终置顶 | 关掉后会被其它窗口盖住 |
| 动画开关 | 关掉呼吸/眨眼/甩尾/散步，适合录屏或嫌晃 |
| 省电模式 | 只保留 1 秒一次的状态检查，几乎不占 CPU |
| 提醒与纪念日设置… | 喝水间隔、睡觉阈值、纪念日 |
| 重置窗口位置与透明效果 | 位置跑偏 / 显示异常时用，回到右下角并恢复不透明 |
| 投喂小零食 | 说一句投喂台词 |
| 退出 | 保存位置后退出 |

### 设置项

- **喝水提醒**：默认 45 分钟一次；浅睡时照常弹（人就在电脑前），深睡时攒着，醒来补弹。
- **睡觉阈值**：默认无交互 5 分钟浅睡、全局空闲 10 分钟深睡。
- **纪念日**：填名称＋日期，启动时说"距离 XX 还有 N 天"，一天只会说一次；点它有 10% 概率被"偷偷告诉"。
- **高 DPI 适配**：改完要重启。

### 换素材

文件名固定，缺哪个就退化成上一级（缺步态帧→用 idle，缺被摸帧→用跳跃，全缺→简笔画），不会崩：

| 文件 | 必需 | 说明 |
|---|---|---|
| `cat_idle.png` | 是 | 待机（2026-10-25 换成新图） |
| `cat_sleep.png` | 否 | 睡觉（2026-10-25 换成闭眼蜷睡版），缺了用 idle |
| `cat_click.png` | 否 | **炸毛**：瞪眼+张嘴+炸毛，2026-10-25 重做 |
| `cat_walk_a/b/c.png` | 否 | 2 张或 3 张都行，自动组循环 |
| `cat_walk_1..8.png` | 否 | 按编号命名时优先用编号（4–6 帧循环走这里），缺了回退到 a/b/c |
| `cat_pet.png` | 是（已提供） | 被摸表情：眯眼+腮红，2026-10-25 重做的实心版 |
| `cat_blink.png` | 否 | **闭眼帧**：有就用真闭眼，没有就把 idle 整体压扁当眨眼 |
| `cat_hold.png` | 否 | **被拎起**：拖动时显示，缺了保持待机图 |
| `cat_eat.png` + `cat_eat2.png` | 否 | **吃东西两帧**（张嘴/闭嘴）：点「喂小零食」时循环约 0.7 秒 |

图片都放在 **`image\`** 子目录里。查找顺序是 **`image\` → 脚本同目录 → `assets\` → 当前工作目录**；`image\` 排第一，是为了避免你把原图丢在程序目录根下时把正式素材顶掉（2026-10-25 踩过这个坑）。

**素材要求**：600×600 或更大（≥2048 会在加载时自动降采样）、RGBA 透明底、白底也行（但要保证背景是纯白）、**脚底基线和 idle 一致**。

### 补帧导入（一条命令）

拿到任何来源的走位图（白底或透明底都行），丢进一个文件夹，跑：

```powershell
python import_frames.py D:\Download\新帧\            # 处理整个文件夹
python import_frames.py a.png b.png c.png            # 或指定图片
# 常用参数
#   --out D:\Download     输出目录
#   --fit per-frame       多张单独生成、大小不一时用（默认 uniform 适合同一张图切出来的）
#   --no-cut              已经是透明底, 跳过抠底
```

它会自动做：抠白底（只删和边界连通的白色，保护肚子里的白毛）→ 切掉地面阴影 → 统一缩放 → 水平居中 → 脚底对齐 → 编号存成 `cat_walk_1..N.png`，最后输出一张深色底预览条给你验收。

## 第一轮：修掉 7 个 bug

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | **睡觉看不到 Zzz** | mask 只覆盖图片 alpha 区，Z 画在留白里被裁掉 | Z 区并入 region |
| 2 | 跳跃峰值切掉图片顶部 5px | `TOP_MARGIN=50` < 跳跃 55 | 留白 64、跳跃 52 |
| 3 | **走动被打断后再也不走** | 步数没清零、`_next_walk` 不重排 | 清步数 + 唤醒重排 |
| 4 | 换帧时猫横移 | 居中了两次 | 只居中一次 |
| 5 | 眨眼整只猫上抬 6% | 顶边对齐压缩 | 底边对齐 |
| 6 | 「重置位置」回到原处 | 复用保存位置 | 先清空再回角落 |
| 7 | 素材缺失抛 `TypeError` | `setMask(QRect)` PyQt5 无此重载 | `QRegion(rect())` |

## 第二轮：5 个（有权限真跑后才暴露）

关动画再开就不散步；睡觉时 `_next_walk` 空转；系统时钟被改导致睡眠判定错（改单调时钟）；改分辨率/拔副屏后猫在屏幕外（每秒校正）；缓存到上限整片清空（改逐出）。

## 第三轮：补帧接入 + 豆包评审的 6 条

| 评审意见 | 处理 |
|---|---|
| ① `_reset_window` 绕过 `_set_state`，`blink/tail_dx/zzz_phase` 没清零 | **采纳**。先显式清动画残留，再走 `_set_state("idle")` |
| ② 浅睡时喝水提醒也被吞 | **采纳**。只有深睡（人明显不在）才攒，浅睡直接弹 |
| ③ `enterEvent` 无条件重置交互计时，鼠标停在猫上就永不睡 | **采纳**。悬停只负责叫醒，不重置计时 |
| ④ Z 区 70×100 的"空气"可点 | **采纳**。改成**位置固定 + 只做透明度渐隐**，框收到 46×62 |
| ⑤ 眨眼时 mask 没跟着压缩 | **保留意见**。见下方说明 |
| ⑥ `_walk_area` 缓存期间任务栏自动隐藏会判错 | **采纳**。只缓存屏幕对象，可用区域每帧重读 |

**⑤ 为什么没改**：眨眼只持续 4 帧（~130ms），偏差是头顶约 13px 的一条带。修它要在眨眼开关时各调一次 `setWindowRgn`，每次都会重建窗口区域，换来的是肉眼根本看不出的点击精度——反而多一个闪一下的风险。所以保持原样，注释里写清楚。

**另外我自己翻出两个补帧的问题**：

1. **步态帧的 mask 缓存没区分朝向**：帧名是 `walk_0/walk_1`，走到屏幕边缘转身后仍命中正向的遮罩，猫身上的可点区域就反了。改成 `walk_0` / `walk_l_0`（带 `_l` 后缀）。
2. **补的两张图取景不一致**：`walk_a` 比 `walk_b` 小 12%、脚底还高 8px，直接交替会"忽大忽小 + 上下弹"。已按 idle 的内容高度（482px）和脚底基线（549px）把两张 2048 图重排成 600×600 再存回 `cat_walk_a/b.png`（原图留在 `walk_*_raw.png`）。

### 被摸帧（cat_pet.png，可选）

交互改成"点一下就摸它"，炸毛留给连戳：

| 操作 | 行为 |
|---|---|
| 单击 | 切 `cat_pet.png` 0.7 秒（眯眼/蹭头）+ 被摸台词 |
| 350ms 内再点一次 | 连戳 → 取消被摸，炸毛跳 + 炸毛台词 |
| 拖动 | 只移动，不播被摸 |
| 悬停（浅睡） | 唤醒 |
| 没有 `cat_pet.png` | 单击自动退回原来的"炸毛跳"，不报错 |

- 优先级：`跳跃 > 被摸 > 睡觉 > 走路 > 待机`；被摸期间不会开始散步，睡着时会被自动清掉。
- 11 项专项检查见 `petcheck_v21.py`（含"没有这张图时"的退化分支）。

**这张是半身特写，和 idle 不同构图，所以单独处理**：按 idle 的**宽度** 475 缩放（头部约 1.3 倍，像凑近镜头），底部贴死画布下沿，胸口直接接到地面、不留悬空。最初按高度对齐试过，头会变成 2 倍大、脚底还浮起来 19px，已废弃。底部 24px 做了 alpha 渐隐，落在地面线上不会出现一条硬切口。

### 关于那 4 帧新走位图

你出的 2×2 拼图里，**每只猫都连着隔壁猫的一条尾巴**（在肩部粘在一起），所以无论按格子切还是按连通域切，切出来都变成"两条尾巴的猫"。我试了两版重建，结果都带双尾，已挪到 `D:\Download\walk4_rejected\`。

现在用的还是原来那 3 帧干净步态（`cat_walk_a/b/c.png`）。要上 4–6 帧，两个办法：

1. **重新出一张拼图**，提示词里加一句「每只猫只有一条尾巴，四只猫之间留出明显空隙，尾巴不要碰到隔壁」；
2. 或者像你之前那样**逐张导出**（当时的单帧是 504px 宽、只有一条尾巴，是干净的），文件名用 `cat_walk_1..4.png`，代码已经支持按编号加载。

## 还没解决的

- **Z 区那 46×62 仍是可点的**：Qt 里遮罩即命中区，要让 Z 画出来就得算进 region。已经是"只包住字形"的极限。
- **走路现在是缓动 + 步态起伏**：起步/收步各 14 帧降到 1px，中间 2px；换脚那一拍身体抬 2px。位移曲线还是线性的，没有真正的加减速曲线。

- **步态帧数还差一口气**：现在是 3 帧（a/b/c）。4 帧拼图那版因为"猫和隔壁尾巴粘连"被拒了，等新的 4–6 帧素材。

## 评价

### 做得还行的地方

- **架构是干净的**：状态机（idle/walk/sleep/deep_sleep）＋ 帧选择（`_frame()`）＋ 渲染（`paintEvent`）三层分开，加新帧只动 `_frame()` 一处；加新状态只动 `_set_state`。
- **可测性意外地好**：所有状态都是实例属性、所有行为都是方法，不用模拟鼠标就能调 `_on_click()/_enter_sleep()/_start_walk()`，13+11 项回归全是"直接调方法 + 断言状态"。这是能连着改四轮不翻车的根本原因。
- **失败路径都留了余地**：缺图退化成简笔画、mask 建失败退化成整窗可点、单实例抢不到锁也照常运行、异常日志限流不刷屏。
- **性能有实测背书**：mask 重建 7.3ms→0.14ms、2x 重绘 0.59ms→0.059ms、空闲 CPU 0.69%、深睡 0.00%、冷启动 0.28s。不是"感觉快了"。
- **细节开始像"产品"了**：气泡贴头顶 6px、被摸有专门的表情和台词、名字贯穿启动语/喝水提醒/菜单/设置标题。

### 还不够好的地方

- **素材是短板，不是代码**：这轮 4 帧走位卡在"拼图里猫和隔壁尾巴粘连"，说明生成工作流不稳定——单帧一次出（像最早那 3 帧）比一张拼图稳得多。
- **单文件 1362 行**已经不是小脚本了。按职责拆 `config / assets / bubble / pet / frames` 更好维护，但单文件"复制一个 .py 就能跑"是真实收益，算取舍。
- **帧动画的物理感弱**：走路匀速平移，没有起步/停下缓动、没有身体起伏。加个 `QEasingCurve` 包络能明显改善。
- **资源路径有三处候选**（exe 旁 / 脚本目录 / assets / cwd），"找不到图为啥"不好查，理想是启动时打一条解析日志。
- **配置全在注册表**：换机器/备份要导出注册表，不如一个 JSON。
- **测试是脚本不是 CI**：得手动跑，没有 pytest 化。

### 一句话

**从"能跑的玩具"变成了"能长期挂着、坏了知道去哪查"的工具。** 代码层面该填的坑基本填完了，现在瓶颈在素材（帧数和一致性），不在实现。真要再往前一步，优先级是：**稳定的 4–6 帧素材 > 走路缓动 > 拆模块**。
